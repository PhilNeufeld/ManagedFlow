# ManagedFlow

A local-first Python application for household asset, cashflow, and
events-and-transitions planning — an Asset, Cashflow, Events and
Transitions Planner. Built to help model the shift from W-2 employment
income to asset-driven income across pensions, PARS, Social Security,
real estate, equity funds, annuities, business interests, and trusts.

## Design philosophy

This is **not** one giant Excel workbook. Python is the calculation
engine; JSON is the storage format; Excel is the output/reporting
layer. Nothing here depends on the cloud — everything runs on your own
laptop, reads/writes plain files on disk, and is auditable line by
line.

The codebase is organized around four core ideas:

- **Entities** are legal/tax holding structures: Personal, Joint, an
  LLC, a Trust, an S-Corp, etc. Every Bundle (see below) is attributed
  to exactly one Entity, so the application always knows "what's held
  inside what."
- **Assets** are modeled as objects (real estate, equity funds,
  annuities, businesses, trusts, cash, pensions). Each asset has a
  starting value, a growth rate, a liquidity category, an optional
  Entity it belongs to, and a collection of cashflows.
- **Cashflows** are the actual dollar movements (rent income,
  mortgage payments, dividends, pension income, living expenses,
  taxes, etc.). A cashflow can be attached to a specific asset, or
  exist at the household level (salary, Social Security, living
  expenses) with no asset attached.
- **Bundles** group related Assets and/or household-level Cashflows
  together under an Entity, so they can be tracked and simulated as a
  unit. "Rental Address 1" is a Bundle: the property Asset plus its
  loan, appreciation, depreciation, rent income, and expenses (which
  already live on the Asset as its own Cashflows). "Spouse A
  Earnings" is also a Bundle, but a cashflow-only one — no Asset, just
  a household-level salary Cashflow. A Bundle needs at least one Asset
  or one household Cashflow to exist.

Scenarios can optionally be scoped to a specific Entity (every Bundle
under it) or a specific set of Bundles, so you can ask "what does the
next 30 years look like for just the rental LLC?" without the rest of
the household's numbers in the way. Leaving a scenario unscoped (the
default) runs the whole portfolio, exactly as before.

A year-by-year simulation engine walks the portfolio (or the scoped
subset of it) forward one year at a time, growing each asset, applying
its cashflows, aggregating household-level cashflows, estimating
taxes, and — if there's a shortfall — drawing down liquid assets in a
defined order (or reinvesting if there's a surplus).

All dollar amounts throughout the application — the Streamlit tables,
the Excel export, anywhere a number is displayed — are shown rounded
to the nearest whole dollar with a `$` sign and thousands separators
(e.g. `$1,234,568`), never with cents. Negative amounts are shown in
accounting style, e.g. `($45,000)`. This is handled by a single
`format_currency()` helper in `models.py` so formatting stays
consistent everywhere.

## Project structure

```
ManagedFlow/
    app.py              Streamlit UI (load/edit/simulate/export)
    models.py           Core dataclasses: Asset, Cashflow, Portfolio, etc.
    storage.py          JSON load/save/validate/backup
    simulation.py        Year-by-year simulation engine
    scenarios.py        Applies scenario overrides to a portfolio copy
    cashflows.py         Withdrawal / liquidity rules engine
    taxes.py             Simplified flat-rate-by-category tax estimator
    exports.py           Excel (.xlsx) report generation
    sample_data.py        Builds a fully fictional sample portfolio
    requirements.txt
    README.md
    data/
        portfolio_sample.json   Generated by sample_data.py
        portfolio.json          Your real working file (not included)
    outputs/
        sample_export.xlsx              Generated Excel report
        YYYY_simulation_results.json    Versioned simulation snapshots
```

## Getting started

1. Install dependencies (ideally inside a virtual environment):

   ```
   pip install -r requirements.txt
   ```

2. Generate the sample portfolio (a fictional household with one of
   every asset type, so you can see the data shapes and try the UI
   before entering your own numbers):

   ```
   python sample_data.py
   ```

   This writes `data/portfolio_sample.json`.

3. Launch the UI:

   ```
   streamlit run app.py
   ```

   From the sidebar, load `data/portfolio_sample.json` to explore, or
   create a new blank portfolio file to start entering your own
   household's assets and cashflows.

## Using it without the UI

Everything the UI does is just a thin wrapper over plain function
calls, so you can drive the whole thing from a script or a Python
shell:

```python
import storage, simulation, exports

portfolio = storage.load_portfolio("data/portfolio_sample.json")

# Run every scenario defined in the portfolio (or an implicit Base
# Case if none are defined):
results = simulation.run_all_scenarios(portfolio)

# Or run just one:
base_case = portfolio.get_scenario("base_case")
result = simulation.run_simulation(portfolio, base_case)

exports.export_to_excel(portfolio, results, "outputs/my_report.xlsx")
storage.save_portfolio(portfolio, "data/portfolio.json")
```

## What's in the sample data

`sample_data.py` builds a fictional household with four Entities:

- **Personal/Joint** — Spouse A & Spouse B
- **Rental Property LLC** — holds the rental property
- **Business Interests LLC** — holds the business interest
- **Family Trust** — holds the trust asset

...and seven Assets distributed across those entities:

- A rental property (mortgage, property tax, insurance, repairs,
  management fee, depreciation placeholder) — under the Rental LLC
- An equity fund (dividends, reinvested dividends, capital gains
  distributions, management fee) — personal
- A cash reserve (interest income) — personal
- An annuity (guaranteed income starting a few years out) — personal
- A pension (CalPERS-style, income-only, no asset value) — personal
- A business interest (illiquid, marked do-not-sell, with annual
  distributions) — under the Business LLC
- A trust (restricted liquidity, with distributions and trustee fees)
  — under the Family Trust

Household-level cashflows include salary income (ending at the
retirement transition), PARS income, Social Security (inflation
adjusted), and living expenses (growing 3%/year) — all personal.

These are grouped into seven Bundles: Rental Address 1, Investment
Portfolio, Retirement Income Sources, Spouse A Earnings (cashflow-only
— no Asset), Household Living Expenses (also cashflow-only), Business
Interest, and Family Trust.

Six scenarios are included: `base_case`, `higher_inflation`,
`sell_rental_2032` (forces a sale of the rental property),
`lower_market_returns` (reduces the equity fund's growth rate),
`rental_llc_only` (Entity-scoped — runs just the Rental LLC's
Bundle(s)), and `spouse_a_earnings_only` (Bundle-scoped — runs just
the cashflow-only Spouse A Earnings bundle). The last two exist purely
to demonstrate scenario scoping; feel free to delete them once you've
seen how they work.

None of this is real financial data — replace it with your own
household's numbers in the UI or by editing the JSON directly.

## The Excel export

`exports.export_to_excel()` produces a 14-tab workbook:

1. Inputs — household + assumptions summary
2. Assumptions — planning horizon, inflation, tax rate table
3. Entities — legal/tax holding structures (Personal, LLC, Trust, ...)
4. Assets — every asset and its key fields
5. Cashflows — every cashflow, asset-attached and household-level
6. Bundles — named groupings of Assets/Cashflows under an Entity
7. Scenario Settings — every scenario, its scope (Full Portfolio,
   specific Entities, or specific Bundles), and its overrides
8. Annual Results — year-by-year household summary, one tab per
   scenario's worth of rows, with surplus/deficit highlighting
9. Asset Detail — per-asset, per-year beginning/ending values
10. Cashflow Detail — per-cashflow, per-year amounts
11. Tax Estimate — estimated tax by category, by year
12. Drawdowns — withdrawal and reinvestment breakdown by year
13. Charts — net worth over time, by scenario, as a line chart
14. Notes / Warnings — anything the simulation flagged (e.g. a
    shortfall that couldn't be fully covered by available assets)

Every value in the workbook is a static, Python-computed number, not
a live Excel formula — this is intentional. The whole point of the
architecture is that Python is the source of truth for the
calculations; Excel is just where you read the results.

## The tax and withdrawal models (intentionally simple)

Per the project's MVP scope, the tax model is a flat rate by category
(ordinary income, capital gains, qualified dividends, rental income,
pension income, annuity income, business income, trust income) — not
a real bracket-based calculation. It's a placeholder structure
designed to be swapped out for something more accurate later without
touching the rest of the simulation engine.

The withdrawal engine draws down assets in liquidity order (liquid →
semi-liquid → restricted → illiquid → income-only → do-not-sell) to
cover any year's shortfall, skipping anything marked `do_not_sell`
unless a scenario explicitly allows illiquid withdrawals. Surpluses
get reinvested into a liquid asset if the scenario says to.

## How inflation works

Two separate growth effects can apply to any cashflow, and they
compound independently:

- **`annual_growth_rate`** on the cashflow itself — a flow-specific
  rate you set explicitly (e.g. "this rental's rent grows 2%/year"),
  always applied.
- **The household's global `inflation_rate`** (in `Assumptions`,
  optionally overridden per scenario) — applied *only* to cashflows
  with `inflation_adjusted=True`. This is meant for things like
  Social Security or general living expenses, where you want them to
  track the household's overall inflation assumption rather than
  having their own separately-tuned growth rate.

If you change a scenario's `inflation_rate_override`, only flows
marked `inflation_adjusted=True` will respond to it — everything else
is governed purely by its own `annual_growth_rate`.

## Entities, Bundles, and scoped scenarios

Three new concepts sit between individual Assets/Cashflows and the
household as a whole:

**Entity** (`models.Entity`) is a legal/tax holding structure:
Personal, Joint, an LLC, an S-Corp, a C-Corp, a Partnership, a Trust,
or Other. Every Entity has an `entity_id`, a `name`, and an
`entity_type`. Assets can optionally reference an Entity via
`entity_id` (replacing the old free-text `entity` field).

**Bundle** (`models.Bundle`) groups related Assets and/or
household-level Cashflows together under one Entity. A Bundle needs
at least one Asset or one household Cashflow — an empty Bundle isn't
allowed. Two shapes show up in the sample data:

- **Asset-centered**: "Rental Address 1" is a Bundle containing one
  Asset (the property), which already carries its own loan, rent,
  appreciation, and expense Cashflows as attached Cashflows on the
  Asset itself.
- **Cashflow-only**: "Spouse A Earnings" is a Bundle with no Asset at
  all — just a household-level salary Cashflow. This is the right
  shape for income or expenses that aren't tied to anything you'd
  call an asset.

**Scoped Scenarios**: `Scenario.entity_ids` and `Scenario.bundle_ids`
let a scenario target a subset of the portfolio instead of running
everything. If you set `entity_ids=["entity_rental_llc"]`, the
simulation pulls in every Bundle under that Entity and runs the year-
by-year engine using *only* those Bundles' Assets and Cashflows —
growth, income, expenses, withdrawals, and net worth are all computed
within that scope alone. `bundle_ids` works the same way but lets you
name individual Bundles directly, regardless of which Entity they sit
under. The two can be combined (the effective scope is the union of
both); leaving both empty is the default and runs the whole portfolio,
unchanged from how scenarios always worked.

This is useful for questions like "how does the rental LLC perform on
its own over 30 years?" or "what does Spouse A's income look like in
isolation?" without the rest of the household's numbers blended in.

In the UI, manage Entities and Bundles from the **Entities & Bundles**
tab, and set a scenario's scope from the **Scenarios** tab when adding
a new scenario (the "Limit to Entities" / "Limit to Bundles"
multiselects). In the Excel export, every Bundle's full member list
and every scenario's resolved scope are shown by name (not raw ids) on
the **Bundles** and **Scenario Settings** tabs respectively.

## Known limitations / good next steps

- **Tax model is a flat rate by category**, not a real bracket
  calculation, standard deduction, or state tax layer. Swapping in a
  more accurate model only requires changing `taxes.py` — nothing
  else depends on its internals beyond the `TaxEstimate` shape it
  returns.
- **No debt/loan balance tracking yet.** Mortgage interest and
  principal are modeled as ordinary cashflows, but there's no
  dedicated `debt_balance` field that amortizes on its own — if you
  want a running loan balance, mortgage payment splits would need to
  be calculated from an amortization schedule rather than entered as
  flat annual numbers.
- **No automated tests yet.** The spec asked for "simple tests where
  practical" — worth adding a small `tests/` directory with a few
  `assert`-based or `pytest` cases around `simulation.py` and
  `scenarios.py`, since those are the modules most likely to grow
  subtle bugs as features are added.
- **Streamlit UI has been exercised against real data, but not in a
  live browser.** Every tab's render function (including the new
  Entities & Bundles tab) was run end-to-end against the sample
  portfolio in this build environment using a stub in place of the
  actual Streamlit framework, which catches logic errors but can't
  verify visual layout, click interactions, or `st.rerun()` timing.
  Run `streamlit run app.py` on your own machine and click through
  each tab once, especially the add/remove forms and the new
  Entity/Bundle creation flow, before relying on it day to day.
